## Goal

Run the release path's `build` and `verify` checks on every pull request into `main` and
every push to it, and make the result a merge requirement. After this story no change
reaches `main` unverified by default, and every exception is deliberate and logged.

## Background

`release.yml` was the only workflow, and it runs on a `v*` tag — so every check this
repository owns first ran on a commit already on `main` and already tagged. Two defects
reached `main` that way in W33, Dependabot's weekly PRs arrived unverified, and PRs #8, #9,
#13 and #14 merged with nothing run on them. [EPIC-10](../epics/EPIC-10.md) §Business context has
the full list; the [design spec](../../superpowers/specs/2026-09-11-pr-ci-gate-design.md)
has the argument; [CONTEXT D50](../../CONTEXT.md) has the decision.

### What "gate" means here

Every account with access to the repository — four on 2026-09-16: `bluezdot`, `hieudd`,
`jindo9986`, `saltict` — holds the `admin` role, and admins bypass the ruleset in mode
`always`. So the ruleset is not a lock. Merging a red or pending PR
takes a deliberate tick on *"Merge without waiting for requirements to be met"* and is
logged; a direct push to `main` lands with `Bypassed rule violations`, is logged, and is
verified after the fact by the `push` run. Dependabot and any non-admin cannot merge red.

- [ ] **AC-3** — **Given** the PR that introduces `ci.yml`, **When** its run completes,

- [ ] **AC-6** — **Given** the ruleset is active, **When** the real PR merges, **Then** it

## Dev notes

### Architecture constraints

- **`release.yml` is not touched.** `ci.yml` copies its steps; it does not share them.
- **`name: verify` is load-bearing** — it is the required check's name.
- **No `paths` / `paths-ignore`** on `ci.yml`, ever, while `verify` is required.

### What we did NOT do

- Did not add a Node matrix, `release:check`, `agile:validate` or a linter to CI.
- Did not require reviews, CODEOWNERS or signed commits, or restrict merge methods.
- Did not enable Dependabot's `github-actions` ecosystem.
- Did not change anyone's repository role.
- Did not commit a copy of the ruleset JSON — see D50 part 5.

## Verification commands

```bash
# AC-1 — pins equal release.yml's (prints nothing on success)
diff <(grep -oE 'uses: [^ ]+' .github/workflows/release.yml | sort -u) \
     <(grep -oE 'uses: [^ ]+' .github/workflows/ci.yml | sort -u)

# AC-2
npm ci && npm run typecheck && npm test && npm run build && npm run release:verify-pack

# AC-3 / AC-5 — the check run's name, app and conclusion for a commit
gh api repos/Koniverse/Senti-MCP/commits/<sha>/check-runs \
  --jq '.check_runs[] | {name, app: .app.slug, app_id: .app.id, conclusion}'

# AC-4 — the live ruleset
gh api repos/Koniverse/Senti-MCP/rulesets --jq '.[] | {id, name, enforcement}'
gh api repos/Koniverse/Senti-MCP/rulesets/<id> \
  --jq '{name, enforcement, conditions, bypass_actors, rules}'

# AC-5 — which step failed, and whether the PR can merge
gh run view <run-id> --json jobs --jq '.jobs[].steps[] | select(.conclusion=="failure") | .name'
gh pr view <pr> --json mergeStateStatus --jq .mergeStateStatus

# AC-7
npm run agile:validate && npm run agile:status
```

## Changelog entry

### `[Unreleased]` — a pull-request CI gate on `main`

Every pull request into `main`, and every push to it, now runs `.github/workflows/ci.yml`:
one job, `verify`, on the Node `22.11.0` floor — `npm ci`, `typecheck`, `test`, `build`,
`release:verify-pack`, the same steps and pins as `release.yml`'s `build` and `verify`
jobs. A repository ruleset makes `verify` a merge requirement, with admin bypass. The
Dependabot header now says what a green PR proves rather than that it proves almost
nothing. Nothing in the package changes.
